Lesson 14 TaskManager JPA Practice

This project is a practice activity for learning Jakarta Persistence. The starter application currently works with an in-memory task service. Your goal is to upgrade it so tasks are stored in a relational database using JPA.

Current Starter Project

  • The JSF task page is already created.
  • The task page currently uses MemoryTaskService.
  • Tasks are lost when the application restarts.
  • Your job is to replace the memory service with a JPA service implementation.

Practice Goal

By the end of this activity, the application should use this architecture: 

TaskCrudView
    -> TaskService interface
        -> TaskJpaService
            -> EntityManager
                -> H2 relational database

Files You Will Create or Update

  • ApplicationConfig.java - defines the H2 JTA datasource
  • persistence.xml - defines the JPA persistence unit
  • Task.java - becomes a JPA entity
  • TaskJpaService.java - implements TaskService using JPA
  • TaskDataInitializer.java - seeds sample data when the database is empty
  • TaskCrudView.java - updated to use the JPA service

Task Entity Requirements

  • Map Task with @Entity.
  • Add a primary key using @Id and @GeneratedValue.
  • Add validation annotations for required fields.
  • Add @Version for optimistic locking.
  • Add createTime and updateTime.
  • Use @PrePersist and @PreUpdate to set audit timestamps.

Important Reminders

  • Do not put EntityManager code in TaskCrudView.
  • Put persistence logic in TaskJpaService.
  • Use the provided IntelliJ IDEA file templates for JPA setup files.
  • The H2 file database will still lose data if drop-and-create is enabled.
  • This practice project is not your Assignment 3 submission.

Application Links

  • Open H2 Console - development/debugging only
